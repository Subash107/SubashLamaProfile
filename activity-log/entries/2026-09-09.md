## Research notes

Returned to the project after roughly two months away and ran a full status audit
rather than any new feature work.

**Findings — repo cadence.** Real feature work stopped at `29bc9be` / `ccc52e1`
(2026-07-04, the workflow YAML repair + activity journal). Everything since is
machine-generated: ~216 `chore:` commits from the scheduled workflows, three
Dependabot bumps, and one README touch on 2026-09-03. The commit graph looks busy
but no human decisions were made in it.

**Findings — CI health.** Scanned the last 200 workflow runs. The 2026-06-26→07-03
cluster of `.github/workflows/*.yml`-named failures is dead history, cured by the
July 4 YAML fix. Three failures are still live:

1. *Evening Recap* — 75 failures, daily since 2026-06-26. Root cause found in
   `evening-recap.yml:45` and `:47`: `TC=$(grep ... | awk ... )` under the runner's
   default `bash -e -o pipefail`. On any day with zero downloads the leading `grep`
   exits 1, pipefail propagates it, and `set -e` kills the step before a single line
   of output. Lines 43–44 are guarded with `|| echo 0`; 45 and 47 were missed.
2. *Weekly Referrer Intelligence* — 10 failures, weekly since 2026-07-03. Same
   class, different line: `referrer-analysis.py` correctly prints `total=0` and
   exits 0, but `BREAKDOWN=$(echo "$ANALYSIS" | grep -v "^total=")` then matches
   nothing, exits 1, and trips `set -e` — before the `if [ "$TOTAL" -eq 0 ]` guard
   two lines below ever gets to skip the run.
3. *Monthly Keyword Gap* — 3 failures, every 1st since 2026-07-01. Log shows
   "Telegram message sent." then exit 1, i.e. `keyword-gap.py` reached its
   `except HTTPError` branch and pushed the real error code to Telegram. Sub-second
   failure points at auth, not timeout — ANTHROPIC_API_KEY likely expired or out of
   credit since the 2026-06-24 setup.

All three share one shape: they were written and tested against a *populated*
download log, and started failing once the data went quiet. Worth remembering as a
pattern — these aren't three bugs, they're one assumption.

**Findings — resume pipeline.** The live site still serves the 2026-06-26 CV
(113,211 bytes, verified over HTTP). A newer `Subash_Lama_CV.pdf` (92,091 bytes)
has been sitting uncommitted in `content/resume/` since 2026-07-08, so CI never
saw it. Also noted a landmine: `sync-resume.ps1:51` picks the *newest* PDF by
timestamp, and the untracked `Subash_Lama_CV_International.pdf` is six minutes
newer — committing both as-is would silently publish the international variant as
the public download.

**Other.** `resume-downloads.txt` has logged nothing since 2026-06-20, which is
either genuinely no traffic or a broken Worker→dispatch path — not distinguishable
without a live test download. Three Dependabot PRs open since July. One high-sev
`brace-expansion` advisory in the dev-only toolchain.

## Research notes — remediation pass

Acted on the audit above. Everything below was verified by execution, not by reading.

**Zero-download guards (committed as `6dd53d5`).** Rewrote the stats block in
`evening-recap.yml` to capture today's log lines once into `TODAY_LINES`, then guard
every derived substitution with `|| true`. Added the missing `|| true` to the
`BREAKDOWN=` line in `referrer-intelligence.yml`. Proved causality rather than
assuming it: extracted each step's shell body straight out of the YAML, ran the
pre-fix version under the same `bash -e -o pipefail` the runner uses and reproduced
exit 1 with zero stdout (matching CI exactly), then ran the post-fix version and got
exit 0. Also exercised the happy path with a synthetic 3-download day — correctly
reported 3 downloads, 3 HOT leads, Microsoft, US.

**A third bug surfaced during that testing.** `referrer-analysis.py` bucketed the
literal string "direct" into "Other", because line 23 only mapped empty/none/- to
"direct" and never the word itself. 6 of the 16 real log rows are literally "direct"
— so the largest single referrer category has always been mislabelled. Fixed by
lowercasing and adding "direct" to the match set.

**The stale CV was an architecture bug, not forgetfulness.** `ci.yml:26` and
`build.yml:26` both run `sync-resume.ps1`, but both check out with
`contents: read` + `persist-credentials: false` and only upload artifacts — nothing
commits the synced PDF back. Cloudflare Pages serves `public/` straight from git, so
CI's resume sync has never once affected the live site. The README claimed otherwise;
corrected it.

Wrote `publish-resume.yml` to actually close this: on push touching
`content/resume/**`, it syncs and commits the published PDF back as
lamasubash107@gmail.com. Path filter is `content/resume/**` while the commit only
touches `public/`, so it cannot retrigger itself.

**A trap found before it fired.** Was about to wire that workflow up when I checked
what `sync-resume.ps1` would actually select in CI. Its "newest wins" rule sorts on
`LastWriteTimeUtc` — but a fresh git checkout stamps every file with the checkout
time, collapsing the sort to the alphabetical tiebreak on line 53. Alphabetically
first is `Subash_Lama_CV.backup.pdf`. So the naive version of this workflow would
have published the backup CV to the live site. Two fixes: an exclusion pattern in
`sync-resume.ps1` so backup/bak/old/draft/copy files can never be candidates, and a
step in the workflow that replays each PDF's git commit date onto its mtime before
sorting, so "newest" means genuinely newest. Verified both by running the script
against a temp source dir with all mtimes forced identical.

**Dependabot.** Merged #21 (fetch-metadata v2 to v3) and #23 (setup-node v4 to v7),
both fully green across all 7 checks. Held #20 (action-send-mail v3 to v18): a
15-major jump, used only by `log-download.yml` and `log-ghost-hit.yml`, whose
GMAIL_APP_PASSWORD was never set — so it is inert today and the upgrade is pure risk.

**Still open, needs Subash.** The monthly keyword-gap failure is an Anthropic API
auth problem (log shows "Telegram message sent." then exit 1 in under a second, i.e.
the `except HTTPError` branch) — the real error code was pushed to his Telegram on
2026-07-01, 08-01 and 09-01. Cannot be fixed from here; the key needs rotating.
Likewise the download log has been silent since 2026-06-20, which no amount of code
reading can distinguish between "no traffic" and "broken Worker dispatch" — that
needs one real test download.
